\subsection{Spatiotemporal Kripke Frame and Contravariant Decay}

A Kripke world $w = (\Lambda, m, n, \nu)$ models the execution environment, where $\Lambda$ denotes the active capability authority set, $m$ is the reference monitor configuration state, $n \in \mathbb{N}$ represents step-indexed metric operational fuel, and $\nu \in \mathbb{N}$ represents the temporal epoch. World accessibility $w \sqsubseteq w'$ (defined as \texttt{world\_accessible} in our development) governs valid temporal and spatial evolution:
\[
(\Lambda, m, n, \nu) \sqsubseteq (\Lambda', m', n', \nu') \iff \Lambda' \subseteq \Lambda \land m \le m' \land n' \le n \land \nu \le \nu'
\]
This relation captures fundamental domain constraints: **spatial contraction** (authority can only be withdrawn or restricted, $\Lambda' \subseteq \Lambda$), **temporal advancement** (epochs monotonically increase, $\nu \le \nu'$), and **metric decay** (fuel strictly decays to ensure termination over steps, $n' < n$ under reduction steps).

\paragraph{Contravariant Capability Decay.}
Capability validity, $\mathtt{valid\_cap}(c, w) \iff c \in \Lambda \land \nu \le \text{cap\_max\_epoch}(c)$, is intentionally non-monotone across forward world evolution ($w \sqsubseteq w'$). Because $w \sqsubseteq w'$ allows spatial revocation ($c \notin \Lambda'$) and epoch expiration ($\nu' > \text{cap\_max\_epoch}(c)$), forward validity preservation ($\mathtt{valid\_cap}(c, w) \implies \mathtt{valid\_cap}(c, w')$) is false by design. Instead, validity exhibits contravariant **backward preservation** under world accessibility: if a capability token $c$ is valid in a future world $w'$, it was necessarily valid in the earlier world $w$.

Within our mechanization, this property is proven unconditionally as a theorem directly from Kripke accessibility parameters:
\begin{lstlisting}[language=Coq]
Lemma valid_cap_monotone : forall (c : Capability) (w1 w2 : World),
  world_accessible w1 w2 -> valid_cap c w2 -> valid_cap c w1.
\end{lstlisting}

\subsection{Dual-Path Logical Relation and Operational Trapping}

The value interpretation $\mathcal{V}_w \llbracket T \rrbracket$ handles capability expiration gracefully through a dual-path operational boundary:
\[
\mathcal{V}_w \llbracket \mathtt{TCap} \rrbracket (v) \triangleq \big(v = \mathtt{e\_invoke}~c \land \mathtt{valid\_cap}(c, w)\big) \;\;\lor\;\; v = \mathtt{e\_val}~0
\]
When a world transition $w \sqsubseteq w'$ causes a capability token $c$ to expire or undergo revocation ($\neg \mathtt{valid\_cap}(c, w')$), semantic value monotonicity ($\mathcal{V}_w \sqsubseteq \mathcal{V}_{w'}$) is preserved because the stale term Safely transition to the trapped operation ($\mathtt{e\_val}~0$) rather than preserving the defunct capability. At runtime, the monitored step relation $\mathtt{step\_m}$ intercepts invalidated capability invocations and transitions them safely via an operational trap ($\mathtt{eff\_trap}$) to $\mathtt{e\_val}~0$, completely decoupling value safety from capability persistence.

\paragraph{Locating and Fixing the Validity Monotonicity Bug.}
During the formulation of our Kripke world accessibility preorder, our initial design relied on a standard domain axiom (\texttt{valid\_cap\_decay\_axiom}) asserting that capability validity is forward-monotone: if $w \sqsubseteq w'$, then $\mathtt{valid\_cap}(c, w) \implies \mathtt{valid\_cap}(c, w')$. When attempting to prove the main soundness theorem, the theorem prover rejected the monotonicity step because forward world transitions ($\sqsubseteq$) allow spatial authority contraction ($\Lambda' \subseteq \Lambda$) and temporal epoch advancement ($\nu \le \nu'$). Forward monotonicity is fundamentally incompatible with capability revocation and temporal expiration. 

By transitioning to a contravariant validity decay paradigm, we proved that validity is backward-preserved (\texttt{valid\_cap\_monotone} in \texttt{World.v}): if a capability is valid in future world $w'$, it was valid at world $w$. 
We reconciled semantic value relation monotonicity ($\mathcal{V}_w \sqsubseteq \mathcal{V}_{w'}$) by defining the dual-path logical relation in \texttt{LogicalRelation.v}, which routes revoked or expired capability invocations deterministically to a neutral trap state ($\mathtt{e\_val}~0$) via the monitored operational step relation $\mathtt{step\_m}$.
